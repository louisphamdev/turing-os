# Turing OS - Quick Start Guide

## Local Compose Setup

### 1. Create local env

```bash
cp .env.example .env
```

Set `LLM_PROVIDER`, `LLM_MODEL`, and credentials in `.env` before starting.
If you use Ollama, `LLM_API_KEY` can stay empty.

### 2. Build images

```bash
docker build -t turing-worker-base:latest ./base-worker
docker compose build turing-orchestrator
```

### 3. Run with docker-compose

```bash
docker compose up -d
```

### 4. Bootstrap Plane + Matrix users

```bash
# macOS/Linux
./init-admin-users.sh

# Windows PowerShell
.\init-admin-users.ps1
```

### 5. Check status

```bash
docker ps
curl http://localhost:3001/health

# macOS/Linux
bash install/config.sh test

# Windows PowerShell
.\install\config.ps1 -Service test
```

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `LLM_PROVIDER` | openai | LLM provider (openai/anthropic/deepseek/ollama/custom) |
| `LLM_API_KEY` | - | Required for hosted providers; optional for Ollama |
| `LLM_MODEL` | gpt-4o | Model to use |
| `LLM_BASE_URL` | https://api.openai.com/v1 | Base URL for OpenAI-compatible API |
| `PLANE_API_TOKEN` | - | Plane auth token (auto-generated by init-admin-users.sh) |
| `PLANE_WORKSPACE_SLUG` | turing-os | Plane project slug |
| `BOOKSTACK_TOKEN` | - | BookStack API token |
| `CONTEXT7_API_KEY` | - | Context7 API key (tech research) |
| `MATRIX_BOT_TOKEN` | - | Matrix bot token (auto-generated by init-admin-users.sh) |
| `MATRIX_ADMIN_USER_ID` | - | Admin Matrix user ID (e.g. @admin:localhost) |
| `MAX_WORKERS` | 5 | Maximum concurrent worker containers |

## Communicating with Workers

After services are running, open **Element Web** at http://localhost:8080 and log in with your admin account.

Each worker gets a dedicated Matrix room (e.g. "Turing - PM", "Turing - PO"). You can:

- **Send messages** directly in a worker's room to chat with the AI agent
- **Use commands** like `/status`, `/timeout-status`, `/unblock <ticket_id>`, `/kill <ticket_id>`
- **Receive notifications** when workers are blocked or complete tasks

## First Successful Run

1. Open Plane at http://localhost:9000 and create a `TODO` ticket with priority `P1`.
2. Open Element at http://localhost:8080 and sign in with the same admin account configured during install.
3. Run `/status` to confirm workers are online.
4. Watch `docker compose logs -f turing-orchestrator` or the worker room in Element to confirm the ticket is picked up.

## Interactive Installer

For a guided setup with all config prompts:

```bash
# macOS/Linux
bash install/install.sh

# Windows (PowerShell)
.\install\install.ps1
```

## Post-Install Config

Reconfigure individual services:

```bash
# macOS/Linux
bash install/config.sh taiga     # Configure Plane only
bash install/config.sh test      # Test all connections

# Windows (PowerShell)
.\install\config.ps1 -Service taiga
.\install\config.ps1 -Service test
```
